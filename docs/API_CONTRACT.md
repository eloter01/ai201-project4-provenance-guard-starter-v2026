# Provenance Guard API contract

This contract describes the planned submission and appeal routes. Send
requests with `Content-Type: application/json` and a JSON object as the body.
Both routes return JSON for success and for the errors listed below.

## `POST /submit`

### Request

| Field | Required type | Description |
| --- | --- | --- |
| `text` | Nonblank string | The writing to score. |
| `creator_id` | Nonblank string | The writer's ID, recorded in the audit log. |

The API sets no maximum character count for `text`. The local detector
requires at least three model tokens and scores up to the first 400 with the
starter configuration. Stylometry measures the full submitted text.
For example, if the detector tokenizer produces 450 tokens, the detector
scores the first 400 and stylometry still measures the full passage.

```json
{
  "text": "I opened the shop at eight. The first customer came in for bread.",
  "creator_id": "writer-17"
}
```

### `200 OK`

| Field | Type | Description |
| --- | --- | --- |
| `content_id` | String | Unique ID for this submission. Use it to appeal the decision. |
| `guess` | String | `human`, `unsure`, or `ai`, based on `confidence`. |
| `confidence` | Number | Combined score used to choose the guess and label. |
| `label` | String | Full sentence for the writing site to display to the reader. |
| `model_score` | Number | Score from the local language model. |
| `style_score` | Number | Score from the stylometry signal. |

All three scores range from 0 to 1 inclusive. Lower values point toward
human writing and higher values point toward AI-generated writing.

| Combined score with starter cutoffs | `guess` | Label category |
| --- | --- | --- |
| `0 ≤ confidence ≤ 0.35` | `human` | High-confidence human |
| `0.35 < confidence < 0.65` | `unsure` | Unsure |
| `0.65 ≤ confidence ≤ 1` | `ai` | High-confidence AI |

The service appends an entry to `logs/audit.jsonl` before confirming the
submission. The entry includes the timestamp, `content_id`, `creator_id`,
`guess`, `label`, and both signal scores. It records `confidence` as
`combined_score` and sets `status` to `decided`.

Example with illustrative scores and label text.

```json
{
  "content_id": "8e6f17b8-2042-4fa9-9dbf-48bccb4f11ba",
  "guess": "unsure",
  "confidence": 0.50,
  "label": "We’re unsure whether this text was written by a person or generated by AI.",
  "model_score": 0.62,
  "style_score": 0.38
}
```

## `POST /appeal`

### Request

| Field | Required type | Description |
| --- | --- | --- |
| `content_id` | Nonblank string | The ID returned by `/submit` for the decision being appealed. |
| `reasoning` | Nonblank string | The writer's explanation of why the decision should be reviewed. |

```json
{
  "content_id": "8e6f17b8-2042-4fa9-9dbf-48bccb4f11ba",
  "reasoning": "I wrote this from my notes about opening the shop."
}
```

### `200 OK`

| Field | Type | Description |
| --- | --- | --- |
| `content_id` | String | The ID of the appealed submission. |
| `status` | String | `under_review`. |

The service appends an entry to `logs/audit.jsonl` with a timestamp,
`event` set to `appeal`, the original decision's `content_id` and
`creator_id`, the writer's `reasoning`, and `status` set to `under_review`.
The original `decided` entry remains in the log. An exact retry with the
same `content_id` and `reasoning` returns the existing confirmation.

```json
{
  "content_id": "8e6f17b8-2042-4fa9-9dbf-48bccb4f11ba",
  "status": "under_review"
}
```

## Error responses

Every listed error includes an `error` string code and a human-readable
`message` string. A required string is invalid if it is missing, `null`,
a different JSON type, empty, or made up entirely of whitespace.

| Routes | HTTP status | `error` | When it occurs |
| --- | --- | --- | --- |
| Both | `400 Bad Request` | `invalid_json` | The body is malformed JSON or its top-level value is something other than an object. |
| Both | `400 Bad Request` | `invalid_field` | A required string is invalid. The message names the field. |
| `/submit` | `400 Bad Request` | `text_too_short` | The detector receives fewer than three tokens. |
| `/appeal` | `404 Not Found` | `content_not_found` | A well-formed request refers to an ID with no recorded decision. |
| Both | `500 Internal Server Error` | `audit_unavailable` | The service cannot write a required audit entry. |
| `/submit` | `503 Service Unavailable` | `detector_unavailable` | The detector cannot load. |

Example `400 Bad Request` response for malformed JSON.

```json
{
  "error": "invalid_json",
  "message": "Send a valid JSON object."
}
```

Example `404 Not Found` response for a well-formed appeal with an unknown ID.

```json
{
  "error": "content_not_found",
  "message": "No decision was found for this content ID."
}
```
